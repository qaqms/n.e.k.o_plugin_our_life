# 我们的生活

养成系陪伴插件：为猫娘维护**饱食 / 精力 / 心情 / 健康 / 好感**五项随真实时间与作息演化的状态，
并以她自己的身心感受**强注入**对话上下文。她有口袋也有背包，**每天会自己吃掉你囤的口粮**——
囤得够、按时回来，日子就过得下去。她还会**自己判断"刚才那轮聊得怎么样"**，
把这个感受轻轻回流成数值。

| | |
|---|---|
| plugin_id | `our_life` |
| 包类型 | `plugin`（完全独立：不调用其它插件、不联网、不改宿主） |
| 存储 | `PluginStore`，**按角色卡分片**（键 `ourlife@<角色名>`） |
| UI | Hosted TSX 面板 `ui/panel.tsx` |
| 默认状态 | **fail-closed：安装后总开关为关** |

## 它做什么

五件事：**数值随真实时间与作息变化**、**她每天要吃饭（口粮要你囤）**、
**她的状态会进入对话**、**她自己的感受会回流成数值**、**你可以从面板看清这笔账**。

- 数值只在你有互动时成长；长期不来会按真实时间衰减（拟真、惩罚式，但有上限，不做不可逆清零）。
- 她有作息：睡眠时段精力回复、饱食掉得慢，你也不会被"她又饿了一点"在凌晨三点叫醒。
- 她每天自己去背包里取口粮吃：**囤的吃完了而你没回来，她就会饿**（饱食掉进"饿坏了"档会主动开口）。
- 状态跨越档位、掉进"生病 / 闹脾气 / 饿坏了 / 累垮了"、或隔了一天你再回来时，插件会把当前状态
  注入她的上下文。
- 面板（v0.4.1 起为「顶部常驻状态带 + 标签页」，v0.4.3 起自动刷新）：状态带常驻五轴数值、今日事实与总开关，
  每 10 秒自动同步一次（防重入 / 后台暂停 / 回可见补拉），不再需要手动点「刷新」；
  四个标签页分别是总览（走势 / 节律）、过日子（口粮顾问、商店、背包）、她的世界（
  **她自己的感受**、她经历过什么）、管理（纠偏、近期注入、配置）。

## 数值机制

| 数值 | 周期 | 衰减 | 静息/地板 | 分档（下界 0/20/40/60/80） |
|---|---|---|---|---|
| `satiety` 饱食 | 小时级 | 清醒 4.0/时、睡眠 1.5/时 ↘ | 地板 0（靠吃饭回来） | 饿坏了 / 有点饿 / 吃饱了 / 吃得很饱 / 撑得慌 |
| `energy` 精力 | 小时级 | 清醒 −2.2/时、睡眠 +6/时；23 点后额外 ×1.35 ↘ | 地板 0 | 累垮了 / 有点累 / 还行 / 精神不错 / 精力充沛 |
| `mood` 心情 | 小时级 | τ = 3h，向静息基线回落 | 基线 55 | 闹脾气 / 低落 / 平静 / 愉快 / 雀跃 |
| `health` 健康 | 天级 | τ = 36h，向静息基线回落 | 基线 70 | 生病 / 虚弱 / 一般 / 良好 / 精神饱满 |
| `affection` 好感 | 周级 | τ = 45d，只缓慢回落、不自动回升 | 地板 0 | 陌生 / 熟悉 / 亲近 / 亲密 / 羁绊 |

- **惰性衰减**：不跑常驻循环，读取时把存值折算到当前时刻，只在写入时落盘。
  进程重启、宿主休眠、电脑关机都不会算错。折算区分**清醒/睡眠**（睡眠窗来自配置，支持跨零点）。
- **跨轴耦合**（不是额外扣分，而是改变时间常数）：
  - 饱食 < 40（掉进"有点饿"）：心情朝向基线掉落的速度 ×1.6；< 20 再 ×1.4；
  - 精力 < 40（掉进"有点累"）：健康朝向基线**恢复**的速度 ×0.55；< 20 再 ×0.7。
  所以饿一天的效果是"心情一路往下掉"，熬夜攒久了会病——因果读得出来，不是凭空 −5。
- **成长**：每次你发言给心情 +2.5 / 健康 +0.8 / 好感 +0.35，同一会话内递减（防连发刷数值）；
  跨天第一次来找她额外给一次"问候礼"；连续相处 3 / 7 / 14 / 30 天各有一次性奖励（含金币）。
- **冷落**：超过 `grace_hours`（默认 24h）没互动后按天扣**心情 / 健康 / 好感**，各自有上限
  （心情最多 −25、健康 −20、好感 −12）。饱食与精力不在这里扣——它们由作息与进食驱动，
  再扣一次就是双重惩罚。
- **纪念日**：相处第 3 / 7 / 14 / 30 / 60 / 100 / 180 / 365 天与之后每个整年，
  当天第一次结算时给一次性礼物，并让模型知道"今天是纪念日"。
- 分档阈值固定在 `core/model.py` 的 `TIER_BOUNDS`、节律常量与耦合阈值也固定在模型里，
  **不作为配置项暴露**（单一来源，避免配置漂移）。
- **分档有两套读法**：面板与"这数值算哪一档"走硬比较（`tier_of`）；
  只有**注入判定**走带 0.05 分迟滞的 `eventful_tier_transitions`。
  原因是默认好评 `20.0` 正好压着 stranger/acquainted 的分界线，硬比较会让**第一拍 30 秒心跳**
  的亚分衰减（→ 19.9998）就触发一次 `tier_change` 强注入，而面板上什么都没变。

## 口粮、金币与背包

这是"每天想回来一次"的来源，也是面板上最实用的一块。

- **她自己吃**：饱食掉到 `meal_threshold`（默认 55，落在"吃饱了"档内）以下时，每次心跳从背包里
  吃掉一份能吃的东西（优先吃你指定/囤的 `staple_item_id`）。没粮就饿着——饱食继续掉，
  掉进"饿坏了"档她会主动开口催饭。
- **金币来源**：当日零花钱（`daily_allowance`，一天一次，跨天自动发）+ 每次发言的日薪
  （`turn_reward`，单次结算最多认 `max_turns_per_session` 次，防一天里刷爆经济）+
  跨天首触奖励 + 连续相处加成 + 里程碑奖励。
- **商店**（物品表固定在 `core/economy.py`，`plugin.toml` 只暴露行为旋钮）：

  | 物品 | 售价 | 效果 | 能吃吗 |
  |---|---|---|---|
  | `meat` 口粮 | 6 | 饱食 +38、心情 +3 | ✅ |
  | `fish` 小鱼 | 10 | 饱食 +38、心情 +6、健康 +2 | ✅ |
  | `cake` 小蛋糕 | 9 | 饱食 +22、心情 +10 | ✅ |
  | `medicine` 药 | 20 | 健康 +18、精力 +6（携带上限 5） | ❌ |
  | `toy` 玩具 | 14 | 心情 +12、精力 +8（上限 3） | ❌ |
  | `gift` 礼物 | 30 | 好感 +4、心情 +8（上限 5） | ❌ |

- **口粮顾问**（面板"算一算"/入口 `advisor`）：按她的真实消耗速度推算
  「每天几餐（理论值 + 最近实测取大者）/ 现有口粮还够几天 / 撑到 7 天还缺几份 / 要花多少金币」，
  并在快见底时标红。**"每天几餐"与真实衰减同源**（共用同一组常量），不是拍脑袋的常数。

## 强注入

触发优先级（事件驱动）：

1. **饿坏了 / 累垮了**：饱食或精力掉进危机档 → 可立即注入，并让她**主动开口**
2. **危机**：心情 / 身体掉进危机档 → 同上
3. **纪念日**：相处天数命中锚点 → 注入一次（当天只一次）
4. **跨档**：任一轴档位变化 → 立即可注入
5. **跨天首触**：今天第一次来找她 → 注入一次
6. **显著漂移**：有新互动、距上次注入已过间隔、且任一轴相对**上次注入时**变化 ≥ 5 分

四层约束（`[our_life.inject]`）：

- `min_interval_sec`（默认 1200s）：常规间隔。**危机与饥/累危机档绕过它**，但仍受小时上限约束。
- `max_per_hour`（默认 3）：所有注入的小时上限。
- `respond_max_per_hour`（默认 1）：**让她主动开口**单独的小时上限——v0.1.0 只有总上限，
  真机上"跨档 + 危机"叠加会连着弹好几次，所以独立限流；额度用完会降级为静默注入，而不是整条丢掉。
- `quiet_during_sleep`（默认 true）：她在睡觉时压住**非危机**注入（凌晨三点把她叫醒说"我饿了"
  与"过日子"的调子相反）；真饿坏了仍然允许，因为那时她本来就该被照顾。

注入契约：

- `ai_behavior="read"` = 进上下文但不打断；`"respond"` = 让她主动开口。`visibility=[]`，
  用户不会看到这段状态说明。`coalesce_key` 让同一条理由折叠成最新一条，不叠成好几遍。
- 正文里**不给模型看原始数字，也不提档位名称**——只有第一人称感受与行为倾向，
  并明确要求她不要复述。给数字会被念出来，给标签会被当台词。
- 正文带 `{MASTER_NAME}` / `{LANLAN_NAME}` 占位符，由宿主按会话展开（插件无从得知该用哪个称呼）。
- 注入模板语言目前固定中文（面向模型的指令性文本）；面板等**用户可见**文案走 `i18n/`。

她还持有三个可自主调用的 LLM 工具：`our_life_feel`（查自己的肚子/精神/心情/身体/关系）、
`our_life_company`（想让你陪她，带 2 小时冷却）、`our_life_judge`（给刚刚那一轮相处打个分，见下节）。

## 她经历过什么（阶段性事件，v0.4.0）

数值只会**连续地**动，但"她病了三天又好了"是一件**发生过的事**，不是一条曲线上的两个点。
这一轮把那种时刻从读数里摘出来，给它一个名字，并落到两个地方：她嘴里（注入叙事）与面板上（经历列表）。

两个事件，两类读法：

| 事件 | 判据 | 她会怎么说 | 睡觉时 |
|---|---|---|---|
| `sick_recovery` 病好了 | 健康从「生病 / 虚弱」跨过 **40** | 主动开口说"那场不舒服终于过去了" | **照说**——那是危机解除的通知，晚八小时就没意义了 |
| `cheered_up` 哄好了 | 心情从「闹脾气」跨过 **20** | 静默进上下文，语气软回来 | 不吵醒她（凌晨三点说这个与"过日子"的调子相悖） |

四条纪律（都写在 `core/events.py` 的模块 docstring 里）：

- **判据线就是档位线**：40 / 20 直接引用 `TIER_BOUNDS`，模块 import 时自检。
  所以"面板显示她脱离了生病档"与"插件认为她病好了"永远是同一个判据；
  它**不随** `[our_life.inject].crisis_*` 那组注入旋钮改动。
- **同轴抑制**：她还在这个轴的危机档里就不发——"你终于好起来了"和"你现在病着"
  摆在同一段上下文里是自相矛盾的。
- **独立注入通道**：事件不挤进常规优先级链（否则"刚病好但还饿着"时会两头互相顶掉），
  只共享 `max_per_hour` 总闸门。
- **事件只叙事、不给数值**：纪念日的礼物照旧归 `[our_life.rhythm]`，
  让"康复"能刷数值会把它变成一条投机的路径。

冷却按事件走：哄好 6 小时（心情是小时级，掉下去又上来是常态）、病愈 20 小时
（允许"隔天又病了、又好了"这种真的两次经历）。面板上的「她经历过什么」比注入记录**更长**——
睡过去的事件也会被记下，只是没有吵醒她。

## 她自己的判断（反馈闭环）

成长原本只按**发言条数**算：连发 20 条「嗯」和认真聊 20 句拿到一样的步长。
她是唯一能判断"这一轮到底怎么样"的一方，所以给她一条回传通道——但**它不是数值写入接口**，
而是一个有上限的修正项。

四个标签 + 一个默认：`wonderful`（特别开心）/ `good`（挺好）/ `neutral`（没什么感觉）/
`dull`（提不起劲）/ `hurt`（有点失落）。她通过 `our_life_judge` 自主回传，**四道闸门**限制它：

| 闸门 | 机制 |
|---|---|
| ① 单次幅度 | 修正量 = 一次真实互动步长 × **0.6**（引用 `turn_*_gain` 常量，不写死数字，所以**永远小于**多说一句话） |
| ② 会话递减 | 同一会话内第 n 次按 `1/(1 + n×0.5)` 递减（跨会话自动回到满步长） |
| ③ 每日上限 | 正向 / 负向**两本独立的账**（默认 8.0 / 4.0），用尽即拒 |
| ④ 真实互动作前提 | `last_touch_at > last_judgment_at`——**没有真实互动就不能加分**，这条最要紧 |

- **负向有自己的闸门**：让工具能扣分等于给模型一条惩罚通道，所以负向日预算只有正向的一半，
  且同样需要真实互动作前提。它只能是"这轮聊得敷衍"的轻微表达。
- **模型的输出当作不可信输入**：标签只认白名单，非法/缺失/大小写混写一律**收敛成
  `neutral`**（不改数值、不报错——报错只会把噪声引回对话）；强度夹到 `(0,1]`；工具**永不抛异常**。
- **反馈不碰饱食与精力**：那两轴由作息与进食驱动，让判断去改会和吃饭打架。
- **返回值绝不带数值**：否则她会开始念叨"我心情 62 分"（与注入契约同一条纪律）。
- 她的判断会作为一条**她自己的感受**进入她的上下文（`trigger=judgment`），
  静默注入、不打扰你；面板"她自己的感受"块摊开今日次数、剩余额度与最近几条。
- 台账**只存标签、时刻与幅度，不存任何对话正文**——工具签名里只有一个枚举 + 一个数字，
  这条路上根本不存在"模型把对话原文写进持久化状态"的可能。

## 按角色卡分片

每个角色卡一套独立数值，键为 `ourlife@<角色名>`。归属判定只认**本次调用注入的
`_ctx["lanlan_name"]`**；后台采样时用总线记录自带的 `lanlan_name`。

> 刻意**不使用** `ctx._current_lanlan` 兜底：那是"上一次调用"留下的脏值，用它会导致
> A 角色的互动记到 B 角色头上（宿主的 `jukebox_controller` 源码里对此有明确警示）。

## 启用与操作

1. 在插件中心导入并启动插件（`auto_start = true`，随宿主启动）。
2. 打开面板 → **总开关**。默认关闭时数值完全冻结：不注入、不结算、不吃饭、不推送，数值原样保留。
3. 打开后开始"过日子"。面板可以查看五项数值、金币与背包、口粮顾问、相处节律与纪念日，
   也能手动纠偏、重置或补贴金币。

### 首次使用建议这样验（5 分钟）

1. 导入后**先打开面板一次**：插件会为该角色卡落一个初始分片（`ourlife@<角色>`）。
   后台心跳没有 `_ctx`，它靠"已知分片 ∪ 总线记录里的角色名"决定结算谁——先碰一次面板，
   冷启动就一定有名单。
2. 打开**总开关**（默认关）。
3. 先看**口粮顾问**：`每天约 N 餐 / 现有口粮 X 份 / 还够 Y 天`，按建议先买够几天的口粮
   （面板"小商店"里可以直接买；新手初始金币 40）。
4. 和她聊几句，等一个心跳周期（默认 30 秒）。
5. 回到面板看四处信号：
   - **相处节律**：`上次互动` 应该变成刚才，`连续相处` 变成 1 天，时段分布出现一格；
   - **她的状态**：心情 / 健康 有小幅上升（每次发言 +2.5 / +0.8，同会话递减）；
   - **口粮顾问**：`今日消费` / `今天吃了` 会动，金币有当日零花钱 + 日薪；
   - **近期注入**：应出现一条记录，触发原因是 `今天第一次来`（跨天首触）。
6. 注入本身在对话里是**看不见**的（`visibility=[]`，只进她的上下文），效果体现在她的语气上。

一个"不看面板也知道她还好吗"的快速判据：**看背包里口粮还够不够**。够了就不用管；
不够就买；一直没买而饱食掉进"饿坏了"，她会自己开口找你。

如果第 4 步之后数值一动不动：先看面板是否显示数值（说明分片在），再看插件日志
`<日志目录>/plugin/N.E.K.O_Plugin_our_life_YYYYMMDD.log` 有没有
`no role resolved from bus conversations` 这条警告——它说明宿主的对话总线记录里没有
可识别的角色名，需要按真实记录形状调整字段映射（日志里已打印记录键名便于定位）。

## 配置

配置分两层：`plugin.toml` 是默认值，用户在
`<用户数据根>/plugins/our_life/config/plugin.toml` 的覆盖层优先。`config.example.toml` 是同一份形状的镜像。

| 键 | 默认 | 含义 |
|---|---|---|
| `[our_life].enabled` | `false` | fail-closed 总开关；关 = 冻结 |
| `[our_life].tick_seconds` | `30` | 后台心跳（采样 + 折算 + 进食 + 结算 + 注入判定） |
| `decay.mood_tau_hours` / `mood_rest_baseline` | `3.0` / `55.0` | 心情的时间常数与静息基线 |
| `decay.health_tau_hours` / `health_rest_baseline` | `36.0` / `70.0` | 健康同上 |
| `decay.affection_tau_days` | `45.0` | 好感衰减周期（好感不会自动回升） |
| `rhythm.sleep_start_hour` / `sleep_end_hour` | `24` / `8` | 作息睡眠时段（支持跨零点；`24` = 24:00） |
| `rhythm.anniversary_mood` / `anniversary_affection` | `12.0` / `5.0` | 纪念日的一次性礼物 |
| `economy.enabled` | `true` | 关闭则她不再自动进食、不发零花钱（只剩纯数值） |
| `economy.staple_item_id` | `"meat"` | 口粮种类（必须是物品表里能吃的东西） |

## 隐私与安全

- **不联网**：插件运行时不发起任何外部请求，不读宿主 `core_config.json`，不做数据出域。
- **不调用其它插件**：完全独立。
- 行为数据只来自宿主只读总线 `bus.conversations`，且只消费 **4 个非正文字段**
  （`conversation_id` / `timestamp` / `lanlan_name` / `turn_type`）。记录里虽然有 `content`
  （对话正文），本插件**不读取、不落盘、不记录**——这条有专门的隐私门测试守着。
- 需要说明的宿主属性：该总线在宿主侧**不按插件隔离**，任何已启用插件都能读到同样的记录。
  本插件的处理方式是"只取非正文字段 + 不落盘"。
- 注入正文含互动节律信息（多久没来、连续多少天），只进总线，不写日志正文。

## 已知限制

- 面板文案有中英两语；其余 6 语言（zh-TW / ja / ko / ru / es / pt）待补，注入模板也暂只有中文。
- 情绪感知（读对话判断心情）**未做**——按要求留待后续以独立插件联动方式接入。
  注意它与"她自己的判断"是两件事：后者是**她自己**回传感受（v0.3.0 已做），
  前者是插件**去读对话正文**推情绪，会碰隐私边界，所以单独立项。
- **反馈闭环取决于 `@llm_tool` 注册成功**：工具的注册经宿主 IPC 转 `main_server` 的
  `/api/tools/register`，宿主在注册失败时**只打 warning 就放过去、且不重试**。
  所以她在 `main_server` 起得比插件晚的那次启动里会暂时"没有判断工具"——
  本插件不受影响（数值、吃饭、注入全部照常），只是那条回传通道缺席；
  重载插件或重启宿主即可恢复。
- 「索取陪伴」等 LLM 工具的注册表在宿主 `main_server` 内存里，宿主重启即丢且宿主不自动重注册；
  本版不做重注册心跳，重载插件即可恢复。
- **面板没有图表组件**（Hosted UI Kit 无图表组件）：近期走势用字符画折线（`▁▂▃▄▅▆▇█`）呈现，
  每条注入带一份数值快照（`{at, stats}`，不含任何正文），只看最近 12 条注入点。
- **她"吃了几餐"是按结算记账的**：关机期间不会补记账（数值照真实时间折算，但餐数统计只在运行时累计）。
- 作息是**配置的固定睡眠窗**，不根据你的互动时段推断（推断错了会明显暴露成"她半夜不困"）。
- 商店物品表固定在 `core/economy.py`，不做抽卡/随机奖励（数值养成的手感来自可预期的规划）。
- **阶段性叙事只覆盖两个事件**（v0.4.0 已做「病愈 / 哄好」）：她判断"这轮聊得不开心"会轻微
  影响数值，但还不会单独成为一个故事事件；同一件事在不同处境下的语气差异（叙事深度）留到下一轮。

## 坑位存档（开发期实际踩到的，供后续维护者省时间）

1. **pytest 会把仓根 `__init__.py` 当模块导入**：它以模块名 `"__init__"` 导入
   `ROOT/__init__.py`，那里有顶层相对导入 → `attempted relative import with no known parent
   package`。解法是 `tests/conftest.py` 预注册 `sys.modules["__init__"]` + 强制所有目录按
   `Dir` 收集（见该文件 docstring）。
2. **`"{MASTER_NAME} ...".format(...)` 会 KeyError**：占位符被当成 format 字段。
   ruff 的 F524 抓到了它，`tests/test_injection.py` 留了回归用例。
3. **ruff 门必须钉 CI 原样参数**：`--ignore-noqa` 意味着本地用 `# noqa` 压掉的问题在市场 CI
   照样算失败（本仓已两次踩坑，故 `release_gate.py` 直接复用 CI 参数）。
4. **子进程管道必须钉 UTF-8**：Windows 默认 GBK 码面，`text=True` 不指定编码会崩 reader 线程
   并丢掉整门日志。
5. **`[plugin.store].enabled = false` 会静默失效**：`set` 返回 `Ok` 却不落盘、`get` 返回默认值。
   有常驻门盯着它必须为 `true`。
6. **`check-hosted-tsx` 要求被检文件在宿主仓内**：所以 hosted-tsx 门走"点前缀探针副本"，
   跑完无条件清理；`.vscode` 必须一起复制（`check -r` 要求仓库支撑文件在位）。
7. **`Grid` 的列数是 `cols`、`Select/NumberInput` 没有 `label`、`StatusBadge` 用 `label`、
   `Tone` 里没有 `neutral`**：照 `plugin/sdk/hosted-ui/index.d.ts` 的精确签名写面板，
   错误 props 会被运行时静默丢弃、布局默默坏。
8. **hosted-tsx 检查器是文本级规则，不跳过注释**：面板注释里写一句 "`api.call()` 返回的是
   信封…" 就会被判成"用了全局 api 对象"而拒收；从 props 解构出与全局同名的短名字同理。
   代码与注释都避开那个标识符的裸形态，一律写完整成员访问。
9. **挂载态（市场 CI）下测试不能依赖真 SDK 的通道**：真 `NekoPluginBase` 会自建真通道，
   而 `bus` 是只读 property；`tests/conftest.py` 因此**无条件**桩掉 `plugin.sdk.plugin`，
   让独立仓态与挂载态行为一致——否则"本地全绿、CI 全红"。
   这正是 `release` 门存在的意义（它真的 `cp` 进宿主仓按裸 id 跑 `check -r`）。
10. **发版链自己的 stdout 也会崩**（第四轮真机实测）：Windows 上 `sys.stdout.encoding` 是
    **活动代码页**（GBK），**被重定向时也一样**——`print("全链通过 ✅")` 直接抛
    `UnicodeEncodeError`，于是"门全 OK、脚本却退 1"，看起来像插件坏了。
    `tools/release_gate.py` 现在按"是否 tty"兜住：重定向重配 UTF-8，真控制台只降 `errors=replace`；
    子进程另用 `PYTHONIOENCODING=utf-8` 钉死。有常驻门（`tests/test_chain_hygiene.py`）守着。
11. **发版链不许依赖网络**（同一轮）：门里原本写 `uvx ruff==<钉住版本>`，而 `uvx` 每次都会去
    PyPI 解析一次——断网时它先红，**后面三门连跑都跑不到**，报告指向错误的方向。
    现在离线优先（uv 缓存命中即跑，版本仍与 CI 逐字一致），缓存未命中才联网；
    绝不用 PATH 上版本未知的 `ruff` 顶包（要顶必须先核对版本）。
12. **分界线上的亚分噪声会被硬比较当成事件**（同一轮，真机 store 里抓到）：默认好评 20.0 正好
    压在分界线上，第一拍 30 秒衰减（→ 19.9998）就发一条 `tier_change` 强注入。
    分档因此有**两套读法**：面板 `tier_of` 用硬比较，注入判定
    `eventful_tier_transitions` 用 0.05 分迟滞。混用任何一套都会回到老 bug。
13. **别把"批准"和"施加"拆成两条判定路径**（v0.3.0 实现期被自己的门抓到）：反馈闭环第一版
    让工具判断后**排队标签**，tick 拿到标签再跑一次闸门判定。结果一次互动被两条路径各判一次，
    而第二拍时 `last_touch_at` 没前进，于是闸门 ④ 把**合法**判断判成
    `judgment_needs_interaction`——数值永远涨不上去，而且日志里一切"正常"。
    修法：工具在调用那一刻判定完并把**已批准的增量**排队，tick 只"施加"不"判定"。
    凡是"闸门依赖随时间变化的状态"的地方都适用这条。
14. **手工造测试分片会让你误判时间语义**（同一轮）：`last_touch_at` 的真值来自宿主总线记录
    自带的 `timestamp`，而手工写分片时会顺手填成本进程的 `time.time()`。两者在真机同源，
    但假数据里会差出一截，于是"看起来像时钟漂移"、差点为它加一个不该有的容差。
    教训：涉及时间的门要走**真实顺序**（真记录 → tick → 断言），不要手编时间戳。
15. **`@timer_interval` 跑在专属线程里，入口/工具跑在另一条线程**（v0.4.x 复核宿主源码
    `plugin/core/host.py:1217-1250` / `:1788`）：timer 是
    `threading.Thread(daemon=True)` + 每拍 `asyncio.run(fn())`，
    而 `plugin_entry` / `llm_tool` / message 走主线程的 command loop。
    **所以 `on_tick` 与入口/工具是真并发，不是同一循环里的交替**。
    本插件两者共享同一份 `ShardState`（`services/state.py` 的 `load` 返回缓存对象、
    `save` 原地更新缓存），`await` 点上存在理论上的读-改-写交错窗口。
    当前**不加锁**：`judgment_*` 轴的唯一写入方就是 `our_life_judge` 自己、
    `daily_allowance_granted` 只有 `_settle` 写，没有第二个写者会丢更新。
    **但这条窗口没有测试门覆盖**——今后新增"入口/工具写、tick 消费"的双写字段时，
    必须回头评估这里（或改成单一队列 / 加 `threading.Lock`）。
